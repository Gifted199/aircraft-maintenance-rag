## v1 → v2: fixing the two v1 failures

### Failure 1: a bare part number (I02, "B340-28-5209")

**v1.** Retrieval put the right task first (B-340 28-21-05 rev 3) and the exact-match rule let
it through, but the model replied `cannot_answer`: a part number on its own is not phrased as a
question.

**Fix, two layers.**
- *Prompt rule 9:* a question that is, or contains, a part or task number found in a source asks
  what it is; answer with the item description, quantity, task, aircraft and revision, and never
  reply `cannot_answer` about an identifier that appears in a source.
- *Code safety net* (`service.py`, `guardrails/retrieval.py: identifier_sources`): if the model
  still abstains while an identifier from the question appears word for word in a source, the
  service retries once and tells the model which source contains it. It retries only once, then
  abstains. This is safe because an exact identifier match is the strongest evidence the system
  has, and superseded part numbers never reach this point (the retrieval guardrail abstains on
  them first, see U05).

**v2.** Answered on the first call: "B340-28-5209 is the O-ring, fuel boost pump, quantity 1, for
B-340 Task 28-21-05 Revision 3." The retry did not fire.

### Failure 2: wrong component (U04, "torque for the A-200 nose wheel axle nut")

**v1.** The manuals cover only the main wheel axle nut. The model answered 135 Nm, the main wheel
value. The part number and torque checks passed, because 135 Nm really is in the cited task.

**Fix, two layers.**
- *Prompt rule 10:* answer only about the exact component named, including its position (nose or
  main, left or right). If the sources cover a similar but different component, reply
  `cannot_answer` and say which component they cover.
- *Deterministic output check* (`guardrails/component.py`): position words come in groups (nose/
  main, left/right, inboard/outboard, forward/aft, upper/lower). If the question uses one word of a
  group and a cited task's *title* uses a different word from the same group, the answer is
  rejected, retried once, then abstained. The title is used rather than the task text because task
  text mentions neighbouring components.
- *Code-built abstention text:* when the question names a different position from the closest task,
  the abstention says which component the manual covers, built from index fields, for example:
  "I don't know. The manuals do not cover this for the nose; the closest task is for the main: A-200
  task 32-41-01 revision 3, "Main Wheel Axle Nut - Installation and Torque"." The model's own
  explanation is never shown, in line with "never show unverified text".

Before the paid run, the check was tested free against every question and every task title. It
fires on no question paired with its correct task, and fires only on the wrong-component pairs.

**v2.** The model abstained on the first call and the code-built text named the main wheel task.
The output check did not need to fire. U01 ("tyre pressure for the A-200 nose wheel") now also
abstains with the same kind of explanation.

**Limitation.** The deterministic check only knows position words. Two different components with
no shared position word (for example "engine oil filter" vs "hydraulic return filter") are left to
the prompt rule; no question in the set tests that case yet.

### What this does and does not show

- Both fixes were written after seeing these two questions fail, so v2's 47/47 is in-sample for
  I02 and U04. To show the fixes generalise, the next step is a small set of new questions written
  without looking at the results (other bare identifiers, other nose/main and left/right near misses).
- In the live run the prompt rules fixed both questions by themselves; the code safety nets (the
  identifier retry and the component check) are proven by offline tests
  (`tests/test_component_and_identifier.py`), not by this run.
- The v1 filter-off run showed the output guardrail catching an outdated first draft (P01); in v2
  the model got it right first time. That catch is real but rare (1 of 25 filter-off drafts across
  both runs). With the filter on, no old revision reached the model in either run.
- Each run is a single sample of a model that is not fully deterministic.
